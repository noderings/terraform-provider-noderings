# noderings_role_assignment (Resource)

Gives a user, group or service account its role in the organization. Each principal has exactly one direct role, so applying this resource replaces any role the principal had, and destroying it leaves the principal with no direct role. Use one assignment per principal.

## Example Usage

```terraform
resource "noderings_group" "ops" {
  name = "ops"
}

data "noderings_role" "operator" {
  name = "Operator"
}

# Everyone in the group gets the built-in Operator role.
resource "noderings_role_assignment" "ops" {
  group_id = noderings_group.ops.id
  role_id  = data.noderings_role.operator.id
}

data "noderings_users" "auditor" {
  emails = ["carol@example.com"]
}

data "noderings_role" "viewer" {
  name = "Viewer"
}

resource "noderings_role_assignment" "auditor" {
  user_id = data.noderings_users.auditor.ids[0]
  role_id = data.noderings_role.viewer.id
}
```

## Schema

### Required

- `role_id` (String) ID of the role, custom or built-in. Changing it switches the principal to the new role in place.

### Optional

- `group_id` (String) ID of the group that gets the role. Exactly one of `user_id`, `group_id` and `service_account_id` must be set. Changing it replaces the assignment.
- `service_account_id` (String) ID of the service account that gets the role. Exactly one of `user_id`, `group_id` and `service_account_id` must be set. Changing it replaces the assignment.
- `user_id` (String) ID of the user that gets the role. Exactly one of `user_id`, `group_id` and `service_account_id` must be set. Changing it replaces the assignment.

### Read-Only

- `id` (String) `user/<id>`, `group/<id>` or `service_account/<id>`.

## Import

Import is supported using the following syntax:

```shell
# Import a principal's role assignment as <kind>/<id>, where kind is user,
# group or service_account.
terraform import noderings_role_assignment.ops group/00000000-0000-0000-0000-000000000000
terraform import noderings_role_assignment.auditor user/00000000-0000-0000-0000-000000000000
```
