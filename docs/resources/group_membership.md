# noderings_group_membership (Resource)

The members of one group. This resource is authoritative for each member type it sets: when `user_ids` is set, users not in it are removed from the group, and likewise for `service_account_ids`. A member type left unset is not managed. Use only one `noderings_group_membership` per group.

Users must already belong to the organization (they join through invites). Find their IDs with the `noderings_users` data source.

## Example Usage

```terraform
resource "noderings_group" "ops" {
  name = "ops"
}

# Users join the organization through invites; look them up by email.
data "noderings_users" "ops" {
  emails = ["alice@example.com", "bob@example.com"]
}

resource "noderings_group_membership" "ops" {
  group_id = noderings_group.ops.id
  user_ids = data.noderings_users.ops.ids
  # Service accounts are managed only when this is set.
  service_account_ids = ["00000000-0000-0000-0000-000000000000"]
}
```

## Schema

### Required

- `group_id` (String) ID of the group. Changing it replaces the resource.

### Optional

- `service_account_ids` (Set of String) IDs of the service accounts in the group. An empty set removes every service account.
- `user_ids` (Set of String) IDs of the users in the group. An empty set removes every user.

### Read-Only

- `id` (String) Same as `group_id`.

## Import

Import is supported using the following syntax:

```shell
# Import the members of a group by the group's ID. Both users and service
# accounts become managed.
terraform import noderings_group_membership.ops 00000000-0000-0000-0000-000000000000
```
