# noderings_role (Resource)

A custom role: a named set of permissions that can be given to users, groups and service accounts with `noderings_role_assignment`. Built-in roles (Owner, Administrator, Billing, Operator, Viewer) are read-only; look them up with the `noderings_role` data source.

## Example Usage

```terraform
data "noderings_permissions" "dns" {
  services = ["DnsZoneService", "DnsRecordService", "DnssecService"]
}

data "noderings_permission" "list_ssh_keys" {
  name = "SSHKeyService::ListSSHKeys"
}

resource "noderings_role" "dns_admin" {
  name        = "dns-admin"
  description = "Manages DNS zones and records"
  permission_ids = setunion(
    data.noderings_permissions.dns.ids,
    [data.noderings_permission.list_ssh_keys.id],
  )
}
```

## Schema

### Required

- `name` (String) Name, 3 to 255 characters, unique in the organization (case-insensitive).
- `permission_ids` (Set of String) IDs of the permissions the role grants. Look them up with the `noderings_permission` or `noderings_permissions` data sources. Permissions added outside Terraform are removed on the next apply.

### Optional

- `description` (String) Description. The API cannot clear a description, so removing this argument keeps the current one.

### Read-Only

- `builtin` (Boolean) Always `false` for roles managed by this resource.
- `id` (String) Role ID.

## Import

Import is supported using the following syntax:

```shell
# Import a custom role by its ID or by its name. Built-in roles cannot be imported.
terraform import noderings_role.dns_admin 00000000-0000-0000-0000-000000000000
terraform import noderings_role.dns_admin dns-admin
```
