# noderings_firewall_ruleset_rules (Resource)

The rules of one firewall ruleset, as one ordered list. This resource is authoritative: it creates, updates, reorders and deletes rules so that the ruleset holds exactly the `rule` blocks in the configuration, in that order, and rules added outside Terraform show up as changes to remove. Use one `noderings_firewall_ruleset_rules` per ruleset.

Rules are evaluated top to bottom, ingress and egress in one list, and the first matching rule decides. Traffic that matches no rule is accepted, so for a default-deny policy end the list with `drop` rules for `0.0.0.0/0` and `::/0`.

Changes reach the virtual machines the ruleset is attached to within about a minute; the API does not report when they are applied.

## Example Usage

```terraform
resource "noderings_firewall_address_group" "office" {
  name  = "office-networks"
  cidrs = ["203.0.113.0/24", "2001:db8:10::/48"]
}

resource "noderings_firewall_ruleset" "web" {
  name = "web"
}

resource "noderings_firewall_ruleset_rules" "web" {
  ruleset_id = noderings_firewall_ruleset.web.id

  # Evaluated top to bottom.
  rule {
    direction         = "ingress"
    action            = "accept"
    protocol          = "tcp"
    destination_ports = "443"
    source { cidrs = ["0.0.0.0/0"] }
  }

  rule {
    direction         = "ingress"
    action            = "accept"
    protocol          = "tcp"
    destination_ports = "443"
    source { cidrs = ["::/0"] }
  }

  rule {
    direction         = "ingress"
    action            = "accept"
    protocol          = "tcp"
    destination_ports = "22"
    source { address_group_ids = [noderings_firewall_address_group.office.id] }
  }

  # Default deny: traffic that matches no rule is otherwise accepted.
  rule {
    direction = "ingress"
    action    = "drop"
    protocol  = "any"
    source { cidrs = ["0.0.0.0/0"] }
  }

  rule {
    direction = "ingress"
    action    = "drop"
    protocol  = "any"
    source { cidrs = ["::/0"] }
  }
}
```

## Schema

### Required

- `ruleset_id` (String) ID of the `noderings_firewall_ruleset`. Changing it replaces this resource.

### Optional

- `adopt_existing` (Boolean) When the ruleset already has rules at create time, take them over: rules that match a `rule` block are kept, the rest are deleted. With the default `false`, creating this resource fails if the ruleset is not empty, so an existing rule list is never replaced by accident. You can also import the rules instead.
- `rule` (Block List) A rule. Order matters: the first block is evaluated first. At most 50 rules per ruleset. (see [below for nested schema](#nestedblock--rule))

### Read-Only

- `id` (String) Same as `ruleset_id`.

## Import

Import is supported using the following syntax:

```shell
# Import the rules of a firewall ruleset by the ruleset ID. All current rules
# are imported in their current order.
terraform import noderings_firewall_ruleset_rules.web 00000000-0000-0000-0000-000000000000
```
