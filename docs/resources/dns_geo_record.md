# noderings_dns_geo_record (Resource)

A geo-routed record: resolvers get an answer chosen by their location. The most specific match wins: region, then country, then continent, then `default`. Only one geo record per name is supported.

## Example Usage

```terraform
resource "noderings_dns_geo_record" "app" {
  zone_id = noderings_dns_zone.example.id
  name    = "app"
  type    = "A"
  ttl     = 60
  default = "192.0.2.10"

  continents = {
    EU = "198.51.100.10"
  }
  countries = {
    JP = "203.0.113.10"
  }
  regions = {
    "US-CA" = "192.0.2.20"
  }
}
```

## Schema

### Required

- `default` (String) Answer for resolvers that match no other rule.
- `name` (String) Owner name relative to the zone, in lower case. Use `@` for the apex.
- `type` (String) Record type: A, AAAA, CNAME, NAPTR, SRV.
- `zone_id` (String) Zone ID.

### Optional

- `continents` (Map of String) Answers by continent code: `AF`, `AN`, `AS`, `EU`, `NA`, `OC`, `SA`.
- `countries` (Map of String) Answers by ISO 3166-1 alpha-2 country code, for example `DE`.
- `regions` (Map of String) Answers by ISO 3166-2 subdivision such as `US-CA`, or a region group such as `US-IX`.
- `ttl` (Number) Time to live in seconds, 30 to 60. Defaults to `60`.

### Read-Only

- `id` (String) `<zone_id>/<name>/<type>`.

## Import
